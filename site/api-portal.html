Home · API Portal

Your proxy login is your API key.

No separate tokens to juggle. Authenticate with HTTP Basic (proxy_user:proxy_pass) or your dashboard session. Full endpoint reference: API Documentation.

Authentication

curl -u USER:PASS https://HOST/api/dev/usage

Use-only credentials: proxy traffic plus usage endpoints. System keys are never exposed to customers.

API keys

View, reveal, copy, and regenerate your key in the portal's API Access page. Regeneration kills the old password at the next 5-minute node sync — by design, not incidentally.

Rate limits

The data plane enforces per-key request limits. Sustained 429 means slow down and spread load; usage endpoints themselves are lightweight reads.

Usage

GET /api/dev/usage returns plan, active status, expiry, and payment history — everything billing dashboards need without scraping HTML.

SDKs

No official SDKs yet — the interface is plain HTTPS + proxy URLs, so requests, axios, fetch, and Go's net/http are the SDK. Copy-paste snippets for all four live in the portal and API Guide.

Error codes

CodeMeaningAction
401Bad proxy login on a use-only endpointRe-copy credentials; rotate if leaked
407Unknown/expired proxy login on trafficCheck status; renew; wait ≤5 min for sync
429Per-key rate limitBack off exponentially

Best practices

  • Environment variables for credentials, never code.
  • One session id per job; rotate to refresh identity.
  • Treat 429 as slow-down and 407 as renew — never retry-storm either.
  • Rotate keys on team changes; old passwords die automatically.
