Home · Docs · Scraper API

One API for web data.

Rendered scraping, structured extraction, SERP, async jobs, and webhooks — keyed to projects, metered honestly. Base URL: https://verdy.vernerx.com. Full machine-readable spec: /v1/openapi.json.

Quickstart

1. Create an account and open the Scraper API dashboard. 2. Create a project. 3. Generate an API key (shown once). 4. Scrape:

curl https://verdy.vernerx.com/v1/scrape \
  -H "Authorization: Bearer $VERDY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://example.com", "render": true}'

Authentication

Project API keys via Authorization: Bearer vdy_… (preferred). Your proxy login (HTTP Basic) and dashboard session also work and map to your Default project. Never put keys in code — use environment variables.

Synchronous scrape

POST /v1/scrape
{"url": "https://example.com", "render": true, "wait_until": "networkidle",
 "timeout_ms": 30000, "screenshot": false,
 "headers": {}, "cookies": [], "viewport": {"width": 1280, "height": 800}}

Optional wait_for_selector, wait_for (ms), full_page, pdf. HTML inlines up to 256KB; larger bodies return a storage ref. Sync slots are limited — use async jobs for bulk.

Structured extraction

POST /v1/extract
{"url": "https://example.com/product/123",
 "schema": {"name": {"selector": "h1", "type": "string"},
            "price": {"selector": ".price", "type": "number"}}}

Selectors: CSS subset (tag/.class/#id/[attr], descendant, child) and a focused XPath subset. Types: string, integer, number, boolean, date, datetime, url, array, object. JSON-LD, OpenGraph, and tables auto-extract alongside. Save reusable schemas as parsers (/v1/parsers, builtins: generic, article, product) and reference by id.

Async jobs

POST /v1/jobs            # {"url": ..., "type": "scrape|extract|serp"}
GET /v1/jobs             # list (?status=&limit=&offset=)
GET /v1/jobs/{id}        # detail (?include=html)
POST /v1/jobs/{id}/cancel

States: queued → scheduled → running → rendering → extracting → completed/failed/cancelled/expired. Retries use backoff; internal retries never double-bill. Idempotency-Key header replays safely.

SERP

POST /v1/serp
{"engine": "duckduckgo", "query": "AI trading platforms",
 "country": "us", "language": "en", "pages": 3}

Engines: duckduckgo (works everywhere), google, bing (both may refuse datacenter automation — the API returns structured ACCESS_DENIED, never fake results). Normalized: position, title, url, domain, snippet, type.

Screenshots

POST /v1/browser/screenshot
{"url": "https://example.com", "full_page": true}

Returns base64 PNG.

Projects, keys, usage, plans

/v1/projects (CRUD), /v1/api-keys (create/list/revoke/rotate — secret shown once), /v1/usage (ledger-backed quotas), /v1/plans (free/pro/business/enterprise limits).

Webhooks

/v1/webhooks (CRUD, HTTPS URLs only) for job.completed|failed|cancelled|expired. Deliveries are HMAC-SHA256 signed (X-Verdy-Signature), retried with backoff, logged at /v1/webhooks/{id}/deliveries. Rotate secrets without downtime.

Errors

Every error is {"error": {"code", "message", "request_id", "retryable"}}. Codes: INVALID_URL, INVALID_REQUEST, SCHEMA_VALIDATION_ERROR, AUTHENTICATION_REQUIRED, INVALID_API_KEY, NOT_FOUND, JOB_NOT_FOUND, CONFLICT, RATE_LIMITED, QUOTA_EXCEEDED, TARGET_TIMEOUT, TARGET_UNREACHABLE, ACCESS_DENIED, LOGIN_REQUIRED, CAPTCHA_REQUIRED, ROBOTS_RESTRICTED, PARSER_ERROR, WORKER_UNAVAILABLE, INTERNAL_ERROR.

Rate limits & quotas

Per-IP, per-key, per-project, and per-endpoint limits (429 = back off). Monthly quotas per plan metered from an append-only ledger. Sync concurrency is capped by worker capacity.

Honest limitations

Jobs run from our worker region — Google/Bing frequently refuse datacenter IPs (returned as structured blocks, not silent failures). CAPTCHAs are detected and reported, never solved. Private/internal URLs are rejected (SSRF guard). Results retained 7–90 days by kind; usage ledger kept indefinitely. Proxy-exit egress for SERP/fetches is on the roadmap, not yet live.

SDKs

No hand-written SDKs: the interface is plain HTTPS + JSON, and /v1/openapi.json is accurate enough to generate clients for Python, TypeScript, and Go.
